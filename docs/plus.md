# Сборы (/плюсы)

Порт логики KillaBot → AkiyamaBot. Ког `bot/cogs/plus.py`.

## Кто что может

| Действие | Кто |
|----------|-----|
| `/плюсы` — создать сбор | **Head VZP**, плюс Leader / Deputy Leader |
| ➕ Плюс / ➖ Минус, тип **Общий** | Любая семейная роль из состава **или** руководство |
| ➕ Плюс / ➖ Минус, тип **VZP** | То же **плюс** роли VZP (см. ниже) |

Тип сбора задаётся в команде и даёт тег при создании (повторно при edit
не пингует). Роли пингов — `PLUS_PING_GENERAL_ROLE_ID` /
`PLUS_PING_VZP_ROLE_ID` в `.env`.

## Плюсы на сборах VZP

Сверх состава и руководства плюсовать VZP-сборы могут держатели ролей
`PLUS_VZP_ROLE_IDS` (`bot/config.py`, по умолчанию — Head VZP; настройка —
через `.env`):

| Роль | Кто это |
|------|---------|
| `1534898714601328670` | Head VZP (ещё и ранг состава) |
| (через `.env`) | тег VZP |
| (через `.env`) | состав «онли VZP» |

На общие сборы эти роли доступа не дают: там по-прежнему нужна семейная
роль или руководство. Проверка срабатывает до модалки статик — кому нельзя,
тот не увидит и её.

**Открывать** сбор (`/плюсы`, любой тип, в том числе VZP) может **Head VZP**
`1534898714601328670` и руководство — проверка `_can_create_plus`.

## Как работает

1. Head VZP / руководство: `/плюсы тип: Общий|VZP причина: … время: 20:00` и
   опционально `нужен_статик`. Без флага статик не спрашивается.
2. Время — `ЧЧ:ММ` по Москве. Если уже прошло сегодня — ставится **завтра**
   (в эмбеде дописывается «· завтра»). В эмбеде — `20:00 МСК` текстом, как
   указал автор: Discord не пересчитывает его в зону читающего (как это было
   с `<t:...:t>`).
3. Бот шлёт эмбед в **этот же канал** с кнопками. `message_id` пишется в
   SQLite (`plus_events`), кнопки с `custom_id` живут после рестарта
   (`add_view` в `cog_load`).
4. **Плюс**
   - не семья → отказ;
   - сбор закрыт/нет → отказ;
   - `нужен_статик` → модалка «Статик», потом запись. Статик — статический
     ID персонажа, только цифры; с буквами/пробелами бот отвечает ошибкой и
     запись не создаёт;
   - иначе сразу в список.
   Повторный плюс **обновляет** запись (тот же человек, новый статик).
5. **Минус** убирает себя из JSON участников.
6. После плюса/минуса сообщение **редактируется**: список заново.
7. Строки участников — **только теги**, форма ники не используется:

   - **нужен статик** — `{n}. <@id> | {статик}`, например `1. <@123456789> | M4`;
   - **без статика** — `{n}. <@id>`, например `1. <@123456789>`. Discord сам
     покажет ник.

   Нумерация — по порядку записи, общая для всех полей списка. Участник,
   ушедший с сервера, в список не попадает. Список длиннее 1000 символов
   режется на несколько полей `Участники (N) · 1/2`.

Авто-сборы: когда по данным vzp-launcher.pro нам забивают деф, бот сам
создает сбор без статиков с заголовком `DEF vs {семья}` (без тега роли —
роль тегается в самом уведомлении о дефе). Подробности:
[`docs/gta5rp-external.md`](gta5rp-external.md#забив-на-нас-деф).

Закрытия сбора в этой версии нет (`is_active` всегда true после создания).
Кнопки на старых сообщениях продолжают работать, пока запись в БД активна.
